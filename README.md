## Project Overview
Project Atlas is an independent project-management case study demonstrating the end-to-end management of a regulated enterprise application modernization initiative.

The project involves replacing a legacy business application with a modern web-based platform, integrating the solution with five enterprise systems, migrating required data, completing formal validation and user acceptance testing, and deploying the solution across multiple geographic regions.

The case study demonstrates practical application of predictive project-management practices across initiation, planning, execution, monitoring and control, deployment, stabilization, and closure.

## Business Context
The existing application has become increasingly costly to maintain and is constrained by legacy technology, fragmented workflows, manual controls, and limited integration with other enterprise systems.

Project Atlas has been initiated to modernize the application while maintaining the traceability, quality controls, documentation, and governance expected within a regulated operating environment.

## Project Objectives
The project aims to:
- Replace the existing legacy application with a modern, supportable enterprise platform.
- Integrate the solution with five upstream and downstream enterprise systems, including the approved Enterprise Regulatory Reporting integration.
- Migrate required operational and historical data to the new platform.
- Establish end-to-end traceability between requirements, testing, validation, and business acceptance.
- Complete deployment within the approved nine-month project window and ₹2.488 crore revised cost baseline.
- Achieve production readiness without unresolved Severity-1 defects.
- Establish structured deployment, hypercare, and transition-to-operations processes.

## Delivery Approach
Project Atlas follows a predominantly **predictive delivery model** because of defined regulatory requirements, formal validation needs, controlled scope baselines, stage-gate approvals, and coordinated production deployment.

The project lifecycle covers:\
**Initiation → Planning → Design → Build → Integration Testing → Validation & UAT → Deployment → Hypercare → Closure**

Formal controls are used for scope, schedule, cost, quality, risk, change, and release management.

## Baseline & Change History

### Baseline Version 1.0
The original Project Atlas baseline included four enterprise integrations, a ₹2.40 crore Cost Baseline / BAC, a ₹0.15 crore Management Reserve held outside BAC, and a planned production Go-Live of 21 August 2026.

### CR-001 — Regulatory Reporting Integration
During project execution and monitoring, a change request was raised to add an Enterprise Regulatory Reporting integration.

CR-001 was assessed across scope, requirements, WBS, schedule, resources, cost, risk, quality and validation, procurement, benefits, and release impact before approval.

The Steering Committee approved CR-001 on 24 April 2026.

### Baseline Version 1.1
Following CR-001 approval:

- Enterprise integration scope increased from four to five integrations.
- Requirements INT-005 and REG-003 were added.
- WBS 4.1.5 — Regulatory Reporting Integration was added.
- The Cost Baseline / BAC increased from ₹2.40 crore to ₹2.488 crore.
- Management Reserve remained unchanged at ₹0.15 crore outside BAC.
- Total Authorized Budget increased from ₹2.55 crore to ₹2.638 crore.
- The approved production Go-Live moved from 21 August 2026 to 28 August 2026.
- Project closure remained 30 September 2026.
- The recurring annual benefit assumption increased from approximately ₹1.30 crore to ₹1.36 crore.

The approved change revised the project baseline without resetting pre-existing execution and cost-performance variance. Historical performance against Baseline Version 1.0 remains traceable through the project change-control records.
