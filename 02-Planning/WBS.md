# Project Atlas — Work Breakdown Structure (WBS)

## 1. Purpose

This Work Breakdown Structure decomposes the approved Project Atlas scope into manageable, deliverable-oriented components and work packages.

The WBS is designed to provide a common structure for:

- Schedule development
- Resource planning
- Cost estimating and budgeting
- Responsibility assignment
- Progress measurement
- Risk identification
- Procurement planning
- Quality and acceptance planning
- Earned Value Management
- Change control

Together with the approved Project Scope Statement and WBS Dictionary, this WBS completes the Project Atlas **Scope Baseline**.

---

## 2. WBS Design Principles

The WBS follows the following principles:

- The structure is primarily **deliverable-oriented**, not a simple activity list.
- The complete approved project scope is represented once within the hierarchy.
- Work packages are defined at a level suitable for estimating, scheduling, assigning ownership, and measuring performance.
- Detailed execution activities will be developed later in the Integrated Project Schedule.
- WBS codes will remain stable unless an approved scope change requires baseline revision.
- Schedule, budget, resource, risk, and performance-control artifacts will reference these WBS codes.

3. **WBS Dictionary**

The Requirements Traceability Matrix supports the scope baseline by maintaining traceability between approved requirements, deliverables, verification, and acceptance.

---

## 4. Baseline Control

The WBS will serve as the coding structure for subsequent planning and control artifacts.

Examples:

- Schedule activities will reference the relevant WBS work package.
- Resource estimates will be assigned against WBS work packages.
- Cost estimates will aggregate from work-package estimates into control accounts and the project Cost Baseline.
- Risks may be mapped to affected WBS elements.
- Earned value performance will be measured using the approved cost and schedule baselines associated with WBS control accounts.
- Approved scope changes will identify the impacted WBS elements before baseline updates are authorized.

Changes to the approved WBS require formal integrated change control.
